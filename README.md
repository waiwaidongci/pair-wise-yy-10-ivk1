# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（经典脚本，无需构建、可走 file://）。

## 改样复确认流程

- 新增作品即登记**初次样稿确认单 v1**（须填联系人），作品自创建起绑定当前确认单。
- 客户改纹样、胎体或线条时登记**变更单**：旧确认单失效，作品停在「待复确认」，
  挂起前工序被记录，复确认通过后自动恢复。
- 变更登记必须包含**联系人、样稿版本、原因**，缺项或提交版本与当前版本不一致返回 **409**；
  版本不一致按乐观并发处理，提示按最新版本重新登记。
- 每件作品同时只能有一份未确认变更，**重复或并发请求沿用首次**登记（返回 reused）。
- 作品必须绑定当前样稿确认单才能进入「待阴干」「待交付」；挂起期间一切流转拒绝（409）。
- 旧样稿版本在履历中**只读留档**；缺陷与流转记录只追加，不覆盖。

## 文件划分（三个业务文件）

| 文件 | 职责 |
| --- | --- |
| `rules.js` | 业务规则纯逻辑：创建、改样、复确认、工序门控、缺陷追加；返回 `{ok,status,message}` |
| `storage.js` | localStorage 持久化、旧版数据迁移（补登 v1 确认单）、种子数据 |
| `page.js` | DOM 渲染与交互：看板、详情履历、改样对话框、409 错误提示 |

页面每次操作后落盘，刷新后看板与履历一致；看板含「待复确认」列，
顶部有「待复确认」风险列表，详情内可查看完整确认履历与只追加的流转日志。
